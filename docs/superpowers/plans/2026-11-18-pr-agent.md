# PR Agent Implementation Plan (phase 2 of 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An opt-in agent that reads a branch's diff through the phase 1 context layer and returns an evidence-cited, teach-first review of it (what changed, what to check, a suggested PR title and description), without ever writing to the repo or sending a secret to a model.

**Architecture:** A new package `gh_analyzer/agents/` that the analyzer core never imports. It builds on phase 1: Tier 0 (`repomap.Tier0`) finds callers of a changed file, Tier 1 (`context.build_tier1`) is the starting context, and Tier 2 is a small set of budgeted read-only tools (diff hunks, file ranges, callers). Every tool result is numbered evidence (E1, E2, ...); a verifier drops any finding its cited evidence does not support. Every string sent to a model passes through one redaction choke point.

**Tech Stack:** Python 3.12, stdlib `urllib` for the OpenAI-compatible client (no new dependency), read-only `git` via the existing `snapshot.git`, pytest with a scripted fake client.

**Spec:** `docs/superpowers/specs/2026-11-18-visualize-and-agents-design.md` (PR agent section). Builds on `docs/superpowers/plans/2026-11-18-context-layer-and-diagrams.md` (done).

## Global Constraints

- **Secrets never reach a model.** Every string sent to the LLM (system prompt, Tier 1 text, tool results, diff hunks, file ranges) goes through `agents.safe.safe_text`, which uses `gh_analyzer.secrets.redact`. This closes the phase 1 gap where `def f(key="sk-...")` and README text sat unredacted in Tier 1.
- **Read-only, never executes repo code.** Git access only through an allowlist of subcommands: `diff`, `show`, `log`, `rev-parse`, `merge-base`, `cat-file`, `diff-tree`. Refs are validated and may not start with `-`. The agent never pushes, comments, merges or writes to the working tree; it returns text for the student to apply.
- **Core stays model-free.** Nothing under `gh_analyzer/` outside `gh_analyzer/agents/` may import `gh_analyzer.agents` (tested). `repo-agent/` is not modified or imported; its pattern (evidence ids, `submit_report`, a separate verifier) is reimplemented.
- **Teach-first, no verdicts.** Output never says approve, reject, merge-ready, plagiarism, copied or original. Checklist items explain why they matter. No effect on any score.
- **Token budget.** Per run: `MAX_STEPS = 8`, `MAX_READS = 6`, `READ_CHARS = 4000` per read, `RUN_TOKEN_BUDGET = 20000` (sum of reported prompt+completion tokens); at the budget the agent is forced to submit. The report carries the total tokens used.
- **Evidence rule.** A finding with no valid evidence id is dropped before verification; a finding the verifier does not confirm is dropped and counted in `report["dropped"]`.
- LLM settings come from environment variables `LLM_API_KEY`, `LLM_BASE_URL` (default `https://api.groq.com/openai/v1`), `LLM_MODEL` (default `openai/gpt-oss-120b`); no `.env` loading, no key is ever logged or stored.
- Phase 1 files are consumed, not modified. Phase 3 (conflict agent) reuses `agents/` modules from this plan: keep them generic over a "context + tools" pair.
- This folder is a git repo holding the user's own uncommitted work: do not commit; a "checkpoint" is the full suite (`python -m pytest tests -q -p no:cacheprovider`, about 3 minutes). Run tests from `GitHub_Analyzer/`.

## Review Focus

1. A diff whose added line contains a secret (`sk-...`, `AKIA...`, `ghp_...`): it must not appear in any message the fake client receives, in the report, or in logs.
2. Zero changed files, or base equal to head: a clean "no changes" report, no LLM call.
3. A huge PR (hundreds of files, a 50,000-line hunk): file list is truncated with a count, reads are capped, tokens stay under the run budget.
4. Renamed, deleted, binary and submodule changes: handled with no crash and a sensible entry in the changed-file list.
5. The model returns malformed tool arguments, non-JSON, or never calls `submit_report`: the run ends within `MAX_STEPS` with a forced conclusion or a plain "could not complete" report, never an exception to the student.

### Task 2: Read-only git access

**Files:**
- Create: `gh_analyzer/agents/gitread.py`
- Test: `tests/test_agents_gitread.py` (use `tests/conftest.py` `make_repo` with branches via `run`)

**Interfaces:**
- Consumes: `snapshot.git(root: Path, *args: str, timeout: int = ..., check: bool = True) -> str`.
- Produces:
  - `ALLOWED = {"diff","show","log","rev-parse","merge-base","cat-file","diff-tree"}`.
  - `class GitReadError(Exception)`.
  - `valid_ref(ref: str) -> bool` (non-empty, no leading `-`, no whitespace or NUL, matches `^[A-Za-z0-9._/@^~{}-]+$` after the first char).
  - `read_git(root: Path, *args: str) -> str` (refuses a subcommand outside `ALLOWED`, any argument that is a ref-position value failing `valid_ref` is the caller's job).
  - `@dataclass Change(path: str, status: str, added: int | None, removed: int | None, old_path: str | None)` with `status` one of `"added","modified","deleted","renamed","binary","submodule"`.
  - `changed_files(root: Path, base: str, head: str) -> list[Change]` (three-dot merge-base semantics: `git diff --numstat -M base...head`).
  - `@dataclass Hunk(index: int, header: str, text: str)`; `hunks(root: Path, base: str, head: str, path: str) -> list[Hunk]`.

- [ ] **Step 1: Write failing tests**: `test_refuses_write_commands` (`checkout`, `commit`, `reset`, `push`, `config`, `apply` each raise `GitReadError` without running); `test_valid_ref_rejects_option_injection` (`--output=/tmp/x`, `-p`, `a b`, `""` are invalid; `main`, `feature/x`, `HEAD~2`, a 40-hex SHA are valid); `test_changed_files_statuses` (a repo with an added, modified, deleted and renamed file gives exactly those four `Change` rows with correct added/removed counts and `old_path` for the rename); `test_binary_change_is_marked` (a file with NUL bytes gives `status == "binary"`, counts `None`); `test_hunks_split` (a file with two separate edits yields two `Hunk`s whose `header` starts with `@@`); `test_identical_refs_no_changes` (`changed_files` returns `[]`).
- [ ] **Step 2: Run** `python -m pytest tests/test_agents_gitread.py -q -p no:cacheprovider`. Expected: FAIL.
- [ ] **Step 3: Implement** in `gitread.py`. `read_git` validates the subcommand then calls `snapshot.git`. Parse `--numstat -z` output so paths with spaces or unicode survive; treat `-\t-` counts as binary; a mode `160000` entry from `git diff --raw` is `submodule`. Raise `GitReadError` (not a raw `SnapshotError`) on an invalid ref or a failed git call.

### Task 3: LLM client with usage accounting and a scripted fake

- Test: `tests/test_agents_llm.py`

**Interfaces:**

  - `class ChatClient(Protocol)`: `chat(messages: list[dict], tools: list[dict] | None = None, temperature: float = 0.2, max_tokens: int = 1500, tool_choice: dict | None = None) -> tuple[dict, Usage]` returning the assistant message dict and the call's usage.
